# TEP 扩展基准与正常训练稳定性研究

本轮把固定九算法从三种故障扩展到官方 20 种故障，每种测试三个独立运行，并用三组互不重叠的正常训练／校准运行重复同一测试集合。2,340 项任务全部成功，没有以改善结果为目的调整参数。结果显示：正常训练运行的选择足以明显改变阈值、算法排序和正常报警负担；晚期名义命中不能替代早期检测或故障特异性证据。

## 数据、协议与覆盖

来源为 [Rieth 2017，Harvard Dataverse V1](https://doi.org/10.7910/DVN/6C3JR1)。实际使用 `TEP_FaultFree_Training.RData`（24,678,017 字节）、`TEP_FaultFree_Testing.RData`（47,327,663 字节）和 `TEP_Faulty_Testing.RData`（836,882,037 字节）；没有使用 Faulty Training。完整大小、MD5、SHA-256 和文件 DOI 保存在[来源清单](../benchmarks/rieth_sources.json)，每次准备缓存均校验原文件。

每个 Testing 运行有 960 个样本、52 个原始过程输入，采样间隔 180 s。时间定义为 `(sample−1)×180`，首个故障样本为 sample 161，即 28,800 s；正常标签结束于 28,620 s。每个 Training 运行有 500 个样本。训练、校准和测试保持独立；故障编号及注入时间只用于评价。

| 研究 | 正常 Fit / Calibration | 相同测试集合 | 正式批次 | 任务 |
|---|---|---|---:|---:|
| 扩展覆盖 | A：Training 1 / 2 | 正常 Testing 1–5；faults 1–20 × runs 1–3 | 3 | 585 |
| 稳定性 | A：1 / 2；B：3 / 4；C：5 / 6 | 与扩展覆盖完全相同 | 9 | 1,755 |

共导入 71 个不同 Dataset：六个正常训练、五个正常测试、60 个故障测试。每个配置、每种方法的故障事件分母为 60，独立正常样本分母为 4,800；故障运行注入前另有 9,600 个正常样本。每个故障／方法单元格有三个事件。三组稳定性配置覆盖全部故障，无需根据第一轮结果挑选代表故障。

协议在评分前固定：[扩展协议](../examples/tep/expanded_protocol.json)、[稳定性协议](../examples/tep/robustness_protocol.json)。九算法及其参数与 [PR22 原协议](../examples/tep/protocol.json) 一致，α=0.01、persistence=3、覆盖门槛 0.9、measured 观测策略。未开展参数搜索。每批至多 28 个 Dataset，即 252 项任务；各配置在所有批次复用一个已拟合模型和校准阈值。扩展研究实际拟合九次，稳定性研究实际拟合 27 次，每条独立测试和 abstain 边界重置时序状态。

## 评价口径

30 分钟、1 小时、4 小时和最终检出均从真实注入时刻计算，窗口右端包含等时刻报警。每个范围内的真值事件都进入各窗口分母；漏检、没有观测和未完成任务分别保留。失败任务的结果未知，展示为 unresolved，不能算成成功，也不伪装成已测量的漏检。本轮全部任务成功、覆盖率 100%、abstain=0，因此所有故障事件均有完整随访。

保留既有形式上的事件命中：故障区间内有 alarm 即算名义命中，包括从注入前延续进来的报警。这衡量报警覆盖，不能单独证明故障导致报警。新增背景对照、注入前报警及注入后报警比例帮助解释该限制。

延迟只描述已命中的事件。报告同时列出漏检数、延迟分布和各早期窗口分母，不把缺失延迟写成零。报警持续时间沿用每个连续片段的末样本减首样本，单点片段为零秒；它不估计样本之间的连续物理报警时长。样本 Recall 与注入后报警比例在本轮完整单故障标签下相同，但仍保留各自的定义和分母。

PCA-Q 的正常误报为 2 / 0 / 0，30 分钟命中为 19 / 22 / 20，最终命中为 51 / 51 / 49。它在本次三组配置下相对稳定，但仍漏掉弱故障，并不构成泛化保证。DPCA-Q 的正常误报为 2 / 5 / 2，30 分钟命中为 20 / 21 / 20，最终命中为 54 / 57 / 55；最后一列包含与正常背景同步的故障 3 命中，不能解释为故障 3 有效识别。

## 故障 3：晚期报警有多少故障相关信息

对同编号正常 Testing 与 fault 3 runs 1–3 做共同 elapsed-time 观察，并读取各自保存的模型与原始 Dataset；没有重新拟合或调整参数。原始 NPZ 的哈希必须与评分快照一致。由已保存 DPCA 的中心、尺度、载荷和 lag padding 重建贡献，逐点验证贡献和与已存 Q 分数一致。

三个 run 在注入前的 160×52 个测量逐值相等，注入后均存在真实差异，全轨迹最大绝对差为 1.9（不同原始变量单位不能直接比较其物理重要性）。run 1 在 167,580±1,080 s 的 13×52 个测量中，438 项相等，最大绝对差约为 0.1；所以不能称为两条完全相同的轨迹。

A/run 1 的正常和故障序列均只在 167,580–167,760 s 有两个报警样本。167,580 s 的正常 Q=140.525005、故障 Q=141.131743，阈值 139.569275；相对于阈值只是有限超出。该局部 13 点分数相关系数为 0.999893676，注入后完整区间分数相关系数为 0.999424766。

同一时刻两序列的前三贡献变量均为 `xmeas_28`、`xmeas_29`、`xmv_11`，正常贡献为 9.4731、9.1234、8.9965，故障贡献为 9.4886、9.0666、8.9892。报告给出这些变量的原始曲线、注入前均值、注入后首小时均值及报警局部均值，同时保留其余八算法在该时刻的分数、阈值、比例与状态。这些贡献是统计残差权重，不是物理根因。

这组证据说明 PR22 的唯一命中对正常背景没有区分力；仅凭该命中不能主张发现了故障 3。其余配置同样没有提供令人信服的故障特异性报警证据。这不等于“故障对测量没有影响”，也没有证明故障 3 绝对不可检测。

原始数据说明把 simulationRun 解释为不同 RNG 状态，并说明训练与测试种子不重叠，但没有明确承诺同编号正常与不同故障的全部物理扰动、噪声生成和随机消耗路径逐点配对。因此本轮把注入前相等、注入后高度相似与报警重合作为实际观察，保留生成机制的不确定性。不能从报警时间相同直接推断种子完全一致。

## 产品集成与保存

研究使用正式 Dataset、Experiment Run、AnalysisResult、标签版本和 Incident。研究模块只组织固定协议、批次与统计，没有复制九算法引擎。`benchmark` 元数据固定协议哈希、研究 ID、训练配置和批次；保存或执行时检查真实源运行、特征、参数、测试范围和真值。跨批次汇总只在同一研究／配置内进行；重复执行选择最新完整执行，并按明确 retry ancestry 合并任务，所有尝试及错误另存审计文件。

TEP 页面可切换原 PR22、扩展和 A/B/C 协议。故障矩阵支持早期／最终事件率、样本 Recall、正常误报、检测延迟和注入后报警比例；点击单元格显示各 run、分母、失败与真实 Dataset／Experiment 链接。具体运行继续使用既有 ExperimentComparison、Plot 和 Signal Explorer。专题正常／故障对照只按模拟 elapsed time 叠加，不把它们写成共同物理时钟。

## 适用条件与后续问题

在本次三组正常来源下，PCA-Q、DPCA-Q 的正常报警负担与早期命中相对稳定，值得作为后续研究基线。它们仍会漏掉弱故障，DPCA-Q 的若干最终命中需要背景对照。EWMA 与两种 CUSUM 对正常来源更敏感；低阈值、时序累积和长测试轨迹能把正常漂移积累为长期报警。Adaptive Max-Z 保留实验性质，C 下也出现正常持续报警。

下一步应先研究多正常运行的校准与独立误报预算、序列长度和累积状态的影响、弱故障与背景峰值的可分性，再研究参数优化。参数开发必须有独立开发／最终测试划分，不能从本轮 20 个测试故障选出最优参数后重新计为独立成绩。还需要更多种子、不同工况及真实工厂测量来检验泛化；当前每故障三个运行只支持描述性结论。
